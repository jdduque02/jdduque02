## 📌 Proyecto Destacado: Cost Manager 💰

Sistema de gestión financiera personal **end-to-end** construido sobre **arquitectura en 4 capas** (Controller → Service → Repository → Entity) con enfoque **Hexagonal**, pensado para escalar como microservicios.

| Repositorio | Descripción | Stack |
| --- | --- | --- |
| [api-cost-manager](https://github.com/jdduque02/api-cost-manager) | API RESTful multi-módulo con autenticación Keycloak, cache Redis, mensajería RabbitMQ, procesamiento asíncrono, notificaciones WebSocket, i18n y auditoría. Documentada con Swagger y cubierta con pruebas unitarias (Jest) + análisis estático (SonarQube). | NestJS 11, TypeScript, PostgreSQL/TypeORM, Redis, RabbitMQ, Keycloak |
| [cost-manager-web](https://github.com/jdduque02/cost-manager-web) | Frontend web moderno con paneles de costos, transacciones y objetivos financieros conectado en tiempo real vía Socket.io. | React 19, TanStack Query/Start, TailwindCSS, shadcn/ui |
| [cost-manager-app-movil](https://github.com/jdduque02/cost-manager-app-movil) | Aplicación móvil para la gestión de costos desde cualquier lugar. | React Native, Expo, TypeScript |

**Arquitectura del backend:**

```
Controller (HTTP) → Service (reglas de negocio) → Repository (persistencia) → Entity (Modelo)
                          ↑ Hexagonal: dominio aislado de la infraestructura
```

**Características principales:**

- 🔐 Autenticación y gestión de identidad con **Keycloak** y JWT.
- 💳 Módulos de **banca**, **catálogo**, **finanzas** y **auditoría** desacoplados.
- ⚡ Cache con **Redis** y mensajería asíncrona con **RabbitMQ**.
- 🔔 Notificaciones en **tiempo real** mediante WebSockets.
- 📄 Procesamiento asíncrono de cargas y archivos sin bloquear la API.
- 🧪 Pruebas unitarias con **Jest** y calidad con **SonarQube**.
- 🚀 CI/CD con **Jenkins** y despliegue contenerizado con **Docker**.

## ⚙️ Servicios Asíncronos

Diseño e implementación de **servicios asíncronos** desacoplados de la API principal, ideales para **cargas masivas de datos** y **procesamiento de archivos** sin bloquear la experiencia del usuario.

```
Cliente / Scheduler → Cola de mensajes (RabbitMQ / Redis) → Worker → Persistencia → Notificación
    Sube CSV/XLSX          Encola el trabajo               Procesa       DB       WebSocket / Email
```

**Casos de uso:**

- 📥 **Cargas masivas de datos** (CSV, XLSX) con validación, transformación y reporte de errores por fila.
- 🧵 **Procesamiento de archivos** (imágenes, PDFs, reportes) en background con workers concurrentes.
- 🔁 **Reintentos automáticos** y colas de mensajes fallidos (dead-letter queues) para trazabilidad.
- 📊 **Seguimiento del estado** de cada job: pendiente → procesando → completado / fallido.
- 🔔 **Notificación de resultados** en tiempo real vía WebSocket o correo electrónico.

## 🧭 Flujo de Trabajo: GitFlow + Conventional Commits

Sigo una metodología **GitFlow** combinada con **Conventional Commits** y **Conventional Branches** para mantener la historia del repositorio legible, las integraciones predecibles y los despliegues controlados.

**Estrategia de ramas (GitFlow):**

```
main ────────────────●─── release/v1.2.0 ──●───────
develop ──●──────────●─────────●────────────●───────
feature/* ──●────────●────── fix/* ...
hotfix/* ────────────────────────●──→ main + develop
```

| Rama | Propósito |
| --- | --- |
| `main` | Producción estable; solo recibe cambios vía `release/*` o `hotfix/*` |
| `develop` | Integración diaria; origen de todas las features |
| `feature/<tipo>-<descripcion>` | Trabajo nuevo (`feat-`, `fix-`, `refactor-`, `perf-`, ...) |
| `release/vX.Y.Z` | Preparación y estabilización de versión antes de llegar a `main` |
| `hotfix/<descripcion>` | Corrección urgente en producción (regresa a `main` y `develop`) |

**Conventional Branches:** `tipo/descripcion-corta` (ej.: `feat/auth-keycloak`, `fix/paginacion-fecha`).

**Conventional Commits:** `tipo(scope): descripcion`

| Tipo | Uso |
| --- | --- |
| `feat` | Nueva funcionalidad |
| `fix` | Corrección de errores |
| `docs` | Documentación |
| `style` | Formato y estilo, sin cambios de lógica |
| `refactor` | Reestructuración sin cambiar el comportamiento |
| `perf` | Mejoras de rendimiento |
| `test` | Pruebas unitarias / e2e |
| `build` | Cambios de build o dependencias |
| `ci` | Configuración de CI/CD |
| `chore` | Tareas de mantenimiento |
| `revert` | Revertir un commit anterior |
